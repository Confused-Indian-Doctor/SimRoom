# Pulse future adapter review — 13 October 2026

Pulse is not installed or used to generate this application's patient state. The functioning `AuthoredPhysiologyAdapter` wraps the deterministic authored-response engine. `src/physiology-adapter.d.ts` defines an external adapter contract for initialise, apply, advance, read, serialise, restore, fork and supports, including explicit variable ownership. A future backend must participate in the existing ownership arbiter; it cannot overwrite faculty pins or run a separate clock.

The [official homepage](https://pulse.kitware.com/) identifies Apache 2.0 licensing and its current generated documentation as 4.4.0. The linked repository NOTICE page was inaccessible during this review; a distributor must inspect the actual chosen release's licence, NOTICE and dependency licences before bundling. No Pulse binaries are distributed here.

The [official interface documentation](https://pulse.kitware.com/physeng.html) exposes explicit time advancement, action processing and state serialisation/restoration. Listed actions include airway obstruction, arrhythmia, intubation, mechanical ventilation, supplemental oxygen, substance bolus/infusion, tension pneumothorax, needle decompression and tube thoracostomy. A native PE mapping for these faculty cases was not established. The [documentation index](https://pulse.kitware.com/_docs.html) provides scenario and data-model references. Integration would require a separately deployed runtime and explicit mappings, with supported-action checks and recorded version/configuration.

The [validation overview](https://pulse.kitware.com/_about_pulse.html) publishes system, compartment and action results across standard patient configurations, with varying agreement. It does not establish validation of these four faculty scenarios, diagnostic images or checklists. The [drug methodology](https://pulse.kitware.com/_drugs_methodology.html) limits drug validation to its standard male patient, describes the oversedation model as rudimentary/unvalidated, and reports a naloxone test with early pharmacokinetic disagreement. That is insufficient evidence to substitute for the missing postoperative pack's qualified naloxone guidance, recurrence and monitoring instructions. No clinical doses from that review have been imported.

Before implementation: select a released build; inspect licensing; document supported case actions and unsupported PE/renal/recurrent-toxicity behaviour; map inputs/outputs with units; preserve the authoritative clock, sample snapshots, pins and deterministic restore; and compare each authored case against its faculty-reviewed objectives and qualifications. These are proposed integration steps, not completed capabilities or clinical validation.
